Data Structures Every CS Student Must Master

Arrays, linked lists, stacks, queues, trees, and hash maps — what each one is actually good for, not just how to implement it.

2026-03-22 · 9 min read · data-structures, cs-fundamentals

Why data structures are worth the effort

A data structure is just a way of organizing data so certain operations — searching, inserting, deleting — are fast. Picking the wrong one doesn't usually break a program; it just makes it slow in a way that only shows up once the data gets large, which is exactly why understanding the trade-offs matters.

Arrays

An array stores elements in contiguous memory, accessed by index. Reading any element by its position is extremely fast, but inserting or removing an element in the middle requires shifting everything after it.

scores = [88, 92, 75, 60]
print(scores[2])  # 75 — instant lookup by index

Good for: fixed-size or rarely-changing collections you access by position, like a list of monthly totals.

Linked lists

Instead of contiguous memory, each element ("node") stores its value plus a pointer to the next node. Inserting or removing at the front is fast, since nothing needs to shift, but finding an element by position requires walking through the list from the start.

Good for: situations with frequent insertions/removals at the ends, like a browser's history "back" list.

Stacks

A stack follows Last In, First Out (LIFO): the most recently added item is the first one removed. Think of a stack of plates — you take from the top.

stack = []
stack.append("a")
stack.append("b")
stack.pop()  # removes and returns "b"

Good for: undo functionality, function call tracking, and parsing matched brackets.

Queues

A queue follows First In, First Out (FIFO): the first item added is the first one removed — like a line at a store.

from collections import deque
queue = deque()
queue.append("first")
queue.append("second")
queue.popleft()  # removes and returns "first"

Good for: task scheduling, print job queues, and breadth-first search in graphs.

Trees

A tree is a hierarchical structure where each node has one parent (except the root) and any number of children. A binary search tree keeps values ordered so that, on average, searching, inserting, and deleting are all much faster than in an unsorted list.

Good for: hierarchical data (file systems, org charts) and fast ordered lookups.

Hash maps (dictionaries)

A hash map stores key-value pairs and uses a hashing function to compute where each key's value should live, making lookups by key extremely fast on average — close to instant regardless of how many items are stored.

student_grades = {"Amy": 91, "Raj": 84, "Noor": 78}
print(student_grades["Raj"])  # 84 — fast lookup by key, not position

Good for: anything you look up by a unique identifier, like usernames, IDs, or word counts.

How to actually chooseAsk what operation your code does most: look up by position (array), add/remove from the ends (linked list/queue), undo the last action (stack), keep things ordered and searchable (tree), or look up by a unique key (hash map). Picking based on the most frequent operation is usually enough to make a solid choice.
