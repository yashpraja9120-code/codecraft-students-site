Building Your First REST API with Python and Flask

A hands-on walkthrough of building a small, real API in Flask — routes, JSON responses, and testing it with your browser.

2026-04-05 · 10 min read · python, flask, web-dev

What you'll build

A small REST API using Flask, a lightweight Python web framework, that serves a list of study tasks as JSON and lets you add new ones. By the end, you'll have a working API you can test directly in your browser or with a tool like the REST Client extension mentioned in 10 VS Code Extensions.

Step 1: Set up the project

mkdir task-api && cd task-api
python3 -m venv venv
source venv/bin/activate   # on Windows: venv\Scripts\activate
pip install flask

Step 2: A minimal working server

Create a file called app.py:

from flask import Flask, jsonify

app = Flask(__name__)

@app.route("/")
def home():
    return jsonify(message="Task API is running")

if __name__ == "__main__":
    app.run(debug=True)

Run it with python app.py and visit http://127.0.0.1:5000/ in your browser — you should see the JSON message. debug=True restarts the server automatically whenever you save a change, which is very useful while learning.

Step 3: Return a real resource

tasks = [
    {"id": 1, "title": "Finish Python roadmap", "done": False},
    {"id": 2, "title": "Practice Git commands", "done": True},
]

@app.route("/tasks")
def get_tasks():
    return jsonify(tasks)

Visiting /tasks now returns the full list as JSON — this is the core idea of a REST API: URLs represent resources, and the response is structured data rather than an HTML page.

Step 4: Accept new data with POST

from flask import request

@app.route("/tasks", methods=["POST"])
def add_task():
    new_task = request.get_json()
    new_task["id"] = len(tasks) + 1
    tasks.append(new_task)
    return jsonify(new_task), 201

This route only accepts POST requests, reads the incoming JSON body, assigns it an ID, and adds it to the list, returning the created task with a 201 Created status code — the conventional response for a successful creation.

Step 5: Look up one task by ID

@app.route("/tasks/")
def get_task(task_id):
    for task in tasks:
        if task["id"] == task_id:
            return jsonify(task)
    return jsonify(error="Task not found"), 404

The <int:task_id> syntax captures part of the URL as a variable, so /tasks/2 looks up the task with ID 2. Returning a 404 status when nothing matches follows the same HTTP conventions real-world APIs rely on.

Why this matters beyond the exerciseThis same pattern — routes, JSON in and out, status codes — is exactly how production APIs work, just with a database instead of a Python list and with authentication layered on top.

What to try next

Swap the in-memory tasks list for a real database (SQLite is a gentle first step), and add basic input validation so a request missing a title doesn't silently break the API.
